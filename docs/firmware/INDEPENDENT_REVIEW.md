## 发现与修正复核

1. **输出脉冲资格判定不完整。** 原实现把单个下降沿视为输出存在，且持续低电平转成无效后会清除失配计时。现由 `core/carbentra_feedback.c` 处理双边沿、至少三个合格周期、7.5–11.5 ms 周期窗、400 µs 毛刺门槛、40 ms 无脉冲与25 ms 持续低电平状态；`main/app_main.c` 在稳定窗口后将持续异常纳入本地故障。主机测试覆盖50/60 Hz、启动、毛刺、丢脉冲和持续低电平。
2. **反馈时间快照可能倒退。** 原毫秒值乘1000后可能早于新捕获的微秒边沿，正常脉冲因此被判为 UNKNOWN。反例中，40500 µs 的有效边沿在40000 µs被判 UNKNOWN，在40700 µs正确判为 AC_PRESENT。现先锁定复制状态，再读取新的微秒时钟。按键保持时也只在实际 ON→OFF 转换更新停启时间，不再反复重置稳定窗口。
3. **命令时间上界误用于签发时间。** 原实现用保守时间上界同时检查签发与失效时间，允许少量未来签发时间通过。现保留可信时间下界和上界，要求签发时间不晚于下界、失效时间晚于上界。位于时间不确定区间的命令有界等待并重新检查；核心回归覆盖边界情况。
4. **JSON 指数溢出绕过非有限值检查。** 原 `1e999` 会变为无穷大，未覆盖的电能和时间字段仍被落库并返回收据。已在内存数据库中复现。现全局拒绝非有限值、过大数值和过深结构，验证相关遥测数值、布尔值及累积量，并禁止序列化非有限 JSON。指数溢出、巨大整数、计数类型和嵌套反例测试通过。
5. **计量芯片单独复位后仍可能标为已标定。** 原采样仅依赖 MCU 启动标志、SysStatus 与 LastData；芯片复位时 SysStatus 为0，CalStart/AdjStart 为0x6886且测量关闭，零读数仍可能通过。现每周期在破坏性电能读取前验证0x8765运行状态、预期CS1/CS2及状态位，失败即清除标定有效性并标记区间不确定。制造商数据依据见仓库 ATM90E26 数据手册的 SysStatus、CalStart、AdjStart 定义。
6. **出队后再赋会话纪元存在重连竞态。** 旧会话命令可能在出队后被赋予新的纪元。现队列元素包含接收时固定的纪元；出队后及动作请求前再次核对会话。此项已作源代码复核；主集成流程已报告修补后的目标构建通过。上述主机测试不模拟真实 MQTT 任务抢占，尚未进行真实重连压力/故障注入测试。

## 仍然有效的验证边界

- 默认继电器驱动保持禁用。真实放行仍需完整电路、每设备真实标定、负载档案和受控调试授权。
- 光耦反馈只能描述检测到的交流脉冲或故障/未知，不能证明无危险电压、机械触点断开或端子可触摸。焊死触点、开路传感链、背馈和非正弦波仍需物理故障测试。
- 64条RAM缓冲不是掉电保持存储。数据库收据与MQTT PUBACK的区分正确，但未送达RAM数据仍可能丢失；电能累计仅覆盖明确有效区间，不能宣称完整计费或经验证减排。
- mTLS、精确主题与本地档案不替代正确的证书、broker ACL、服务器时间源、生产安全启动/密钥管理及真实重连测试。
- 标定CRC只检出意外损坏，不能证明标定真实、配置授权或器件精度。LastData校验与运行状态检查也不是电气故障覆盖率认证。
