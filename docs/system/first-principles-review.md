# 系统原理与仍需验证的假设

目标是在安全、设备寿命、使用需求和舒适度约束内改善用能，而非单纯增加联网开关。

1. 物理测量：瞬时电压电流共同决定有功功率，时间积分决定电能。非线性负载不能用电压有效值乘电流有效值冒充有功功率。低功率误差、标定、滤波和采样时间影响识别上限。
2. 可观测性：板温、接触点温度、环境温度和实际输出供电状态各自对应不同物理对象；命令不能代替观测。
3. 可控性：统一设备平台必须保留负载能力约束；供电口并不天然提供空调温度等设备内部控制接口。软件不能提升物理插接与载流额定能力。
4. 闭环：观察、策略、动作、反馈与效果验证分别留证；网络送达、线圈动作、触点状态与设备运行不同。
5. 优化目标：节能、削峰、电费和碳核算分别计量；固定碳因子下，仅转移用电时段不能自动宣称减少排放。
6. 分层职责：端侧处理本地约束，边缘协调多个设备，云端负责广域分析和模型管理。关键保护不依赖网络或单一软件通道。
7. 故障与安全：断网、时钟错误、重放、传感器故障、触点焊死、升级失败和大量设备同步恢复必须定义处理方法。检测异常不等于已经消除危险。
8. 机械与热：电源余量、器件发热、天线环境、绝缘、固定和墙面支撑力矩必须共同审查。几何无干涉不是热或机械寿命验证。
9. 效果证据：计量缺失、启动纪元、总分表关系、气象/课程差异、终端自身耗电与基线选择决定结论可信度。以简单策略作为对照，不能预设 AI 一定更优。

当前能够提供的是可追溯数字设计、程序与测试；真实硬件验证、每台标定、校园场景数据和运行授权仍需外部证据，不可编造。
